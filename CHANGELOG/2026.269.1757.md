# 2026.269.1757 — docs(skills): name the kindcluster sibling in kubernetes + check-k8s

## Summary

The Kubernetes deploy surface gained a **local-cluster sibling** — `kindcluster`
(`kind: kindcluster`, a `kindcluster:` entity), served by the `deploy:kindcluster`
provider beside `deploy:kubernetes` in `candy/plugin-kube`. This change cross-references
it from the two skills that describe that surface, so an agent reading them knows the
local-engine option and the **shared** `kube:` probe path:

- **`check-k8s-skill`** — after the "deploy KIND is spelled `kubernetes`" note, a
  paragraph naming `kindcluster` as the local-cluster sibling (kind provisions node
  containers on the operator's engine — docker / rootless podman / rootless nerdctl —
  instead of a VM) and recording that a `kindcluster:` deploy writes a `kind-<cluster>`
  kubeconfig context the same `kube:` verb addresses with `kube_context:`.
- **`kubernetes-skill`** — a paragraph after the Overview recording that the local
  sibling reuses the same Kustomize + `kubectl` machinery, served by `deploy:kindcluster`
  beside `deploy:kubernetes` in `candy/plugin-kube`.

Both point at the canonical `/charly-kubernetes:kind` skill.

Prose only — no entity, schema, plan, or pin changes.
